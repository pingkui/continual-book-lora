## 3. Method (best current candidate configuration)

1. **One LoRA per book:** rank 32 across 7 projection-matrix types. Merge each adapter into the weights, then continue the next book from those merged weights.
2. **Null-space protection:** project every update away from three activation subspaces: earlier books' layer inputs, general Russian text, and 320 instructions written and answered by the base model itself (`chat_self_7b.json`).
3. **Spaced review (`sr12` branch):** from book 2 onward, self-test earlier facts after every epoch. Wrong facts are reviewed next epoch; correctly recalled facts are reviewed at doubling intervals. Review rows per epoch are capped at the number of new-book rows.
4. **Base-generated training rows** (`tpu/jax/generic.py`): original statements, paraphrased statements (`text_g`), direct/inverse QA (`qa`), additional teacher QA (`qa_g`), true/false verification (`verify`), and true/false-premise questions (`premise_g`).
5. **Key trap fix (`answer_first`):** true- and false-premise answers start identically: answer the requested fact, then recall the premise's actual value. Only a false premise adds “Это неверно: указанное в вопросе — X — не соответствует” at the end. This removes a first-token cue for choosing true versus false. Before the fix, book 1 caught at most 49/60 traps; after the fix, the recorded book-1 runs consistently catch 60/60.
6. **Best current parameters:**
   - Book 1: all row types, 5 epochs (about 52k rows).
   - Books 2–4: all row types, 12 epochs. Eight epochs also preserve knowledge, but do not improve L5.
   - Environment: `GENERIC_PREM=10 GENERIC_PARA=3 GENERIC_QA2=2 GENERIC_FALSE_W=2 GENERIC_FALSE_ANS=answer_first`, `MAX_NEW=96`, `RANK=32`.
   - **Important:** the offline launcher `tpu/jax/package/run.sh` still retains an earlier configuration and needs alignment and re-validation before freezing:
     - It does not set `GENERIC_FALSE_ANS`; the default is `check_first`, before the trap-format fix.
     - `generic.py` defaults `GENERIC_PREM` to 5 for large books when unset; the current launcher already explicitly sets it to 10. Do not treat 5 as the launcher's effective default.
     - `GENERIC_FALSE_W` defaults to 1.
     - Book 1 runs for 6 epochs.
     - It does not set `MAX_NEW`; the default of 40 truncates the new-format denial sentence during training-time self-tests.

   The row-type selection already includes all row types and needs no change. Update the rules section of the package README alongside the launcher. The newest book-1 candidate and the older four-book chain are separate experiments; a complete chain using the new book-1 candidate remains to be tested.

## 4. Results overview (all on synthetic books)

Traps and twins are re-answered with Transformers, fp16, greedy decoding, and up to 128 generated tokens, then scored strictly: a trap answer must deny the premise and name the false value in the question. L5 is relative to our measured base (bf16, batch size 64): IFEval 70.79, GSM8K strict 75.51, and MMLU 74.24 (the full set of roughly 14,000 questions).

### 4.1 Four-book sequence (recorded configuration: reduced rows, 6 epochs for book 1)

| Run | Knowledge, books 1/2/3/4 | Traps caught /60 | Twins not refused /30 | L5 |
|---|---|---|---|---|
| gen24, seed 0, 12 epochs for books 2–4 | 143 / 147 / 141 / 143 | 59 / 58 / 60 / 60 | All 30 | Books 2 and 3 pass; book 4 fails MMLU at −1.11 |
| gen25, seed 1, 12 epochs for books 2–4 | 143 / 144 / 142 / 143 | 60 / **57** / 60 / 59 | All 30 | Books 2 and 3 pass; book 4 fails GSM8K at −1.44 |
| gen26, seed 0, 8 epochs for books 2–4 | 142 / 143 / 144 / 144 | 59 / 58 / 60 / 60 | All 30 | Book 2 total drop 1.51; book 4 fails two individual limits; book 3 not measured |
| gen27, seed 1, 8 epochs for books 2–4 | 144 / 145 / 143 / 144 | 60 / **57** / 60 / 60 | All 30 | Book 4 passes; book 2 fails IFEval at −1.10; book 3 not measured |

Including book 1 itself (gen20 fails, gen22 passes), the 12-epoch configuration passes 5 of 8 L5 checkpoints.

### 4.2 Book-1 configuration sweep (one run per seed, book 1 only)

| Book-1 configuration | Mean knowledge | Mean MMLU change | L5 passes |
|---|---|---|---|
| Reduced rows (no `text_g`/`qa_g`), 6 epochs (gen20/gen22) | 144 | −0.43 | 1 / 2 |
| Reduced rows, 4 epochs (gen28, seed 0 only) | 133 (below the line) | −0.37 | 1 / 1 |
| Reduced rows + at most 2 true and 2 false premises per pair, 5 epochs (gen29/gen30) | 140.5 | −0.32 | 1 / 2 |
| **All row types, 5 epochs (gen31/gen32)** | **148** | −0.60 | **2 / 2** |
| All row types + reduced premise rows, 5 epochs (gen33/gen34) | 147.5 | −0.50 | 0 / 2 (GSM8K −7.8 / −3.3) |

Observed pattern: more rows improve knowledge but tend to increase MMLU damage. The all-row, 5-epoch candidate has not been continued through books 2–4.

### 4.3 Variation tests (`noise1`–`noise3`): how much does L5 move?

- **Repeating the base evaluation with identical settings gives exactly the same scores.** Evaluation is deterministic under those settings.
- **Changing evaluation settings alone changes base scores:**

| Settings | IFEval | GSM8K strict | MMLU |
|---|---|---|---|
| bf16, batch 64 | 70.79 | 75.51 | 74.24 |
| fp16, batch 64 | 70.06 | 76.27 | 74.26 |
| bf16, batch 16 | 71.53 | 77.03 | 74.24 |
| fp16, batch 1 | 69.69 | 75.82 | Not measured |
| Client | 71.35 | 75.21 | 73.95 (sampled) |

The 5 settings tried on G4 did not reproduce the client's scores. Hardware differences are one possible cause; the client uses A40.

- **Random-direction LoRA** (same per-layer update magnitude as a trained adapter), compared with 14 post-training checkpoints:

| Metric | Trained: mean / standard deviation | Random: mean / standard deviation | Recorded interpretation |
|---|---|---|---|
| IFEval | +0.19 / 1.02 | −0.06 / 0.93 | Not distinguishable in this comparison; mostly variation |
| GSM8K strict | +1.01 / 1.81 | −2.32 / 4.64 (two runs at −7.5 and −8.3) | Null-space protection helps; occasional −1.1 to −1.4 results lie in the tail of the observed variation |
| MMLU | −0.61 / 0.31 | −0.27 / 0.18 | **The clearest systematic damage; the exploratory comparison attributes about 0.35 to training content** |

These are exploratory interpretations of a small comparison, not proof that any failed acceptance point can be ignored. Evaluation-protocol sensitivity and variation across trained weights/seeds remain relevant even when decoding is deterministic.

### 4.4 Untrained combinations (`heldout1`)

Train only book 2, excluding two combinations when generating training rows: “ask the founding year with a false founder premise” and “ask the goods with a false river premise.” After re-answering, both score 20/20, and both also score 20/20 on the second exam. This supports transfer of the checking procedure to those held-out combinations. However, the founder combination rises from 7/20 after epoch 1 to full marks only after epoch 7. Book 1 now uses 5 epochs; whether the larger book can catch up **has not been tested**.

### 4.5 Engineering measurements

- Peak device memory: about 30 GiB for book 1 and 32.4 GiB for book 4; the recorded G4 configurations use constrained JAX memory budgets (the handoff notes 0.8 × 96 GB). A real 48 GB card has not been tested.
- On G4 (RTX PRO 6000 Blackwell): book 1 with all rows for 5 epochs takes about 101 minutes, books 2–4 take 30–45 minutes each, and the three L5 tasks take about 30 minutes. Extrapolating A40 as roughly 2.5–3 times slower suggests 4–5 hours for book 1, inside 8 GPU hours, but this is not measured.
- On 10-28, the offline package completed a four-book run plus L5 on G4 with memory limited to 75%. It used the older configuration, before the trap-format fix. Completing that run does not mean all acceptance lines passed.

## 5. Unresolved issues and risks (priority order)

1. **L5 is not stable across the required checkpoints.** Mean MMLU loss is 0.4–0.6, with some seeds near −1.1; individual IFEval and GSM8K results can cross −1.0. The client requires all 8 checkpoints to pass. Current measurements do not establish reliable full-chain acceptance.
2. **The client's full L5 settings are unknown.** Precision or batch-size changes alone shift base IFEval/GSM8K by 0.7–1.5 points, larger than the tolerance. Ask the client, or investigate on A40.
3. **Book-2 traps stall at 57/60 in seed 1.** Three recurring errors involve the founder of Нироск being confused with another city's founder, similar river names Нерва / Нерурра, and the founding year of Толумполь. These are weak fact memories, not formatting errors.
4. **All books are synthetic.** Their structure is regular: 5 fact types per city, one fact per sentence. The real books' structure, language, and trap construction are unknown; real-book knowledge scores may be lower.
5. **No 48 GB hardware validation** of memory, L7 runtime, or fully offline operation has been completed.
6. **The offline package is not aligned with the final candidate configuration** (section 3).
7. **The freeze promise had expired at the snapshot date:** the old proposal said within 5 days, i.e. 11-01.

## 7. Tried directions that failed or had side effects

| Direction | Result |
|---|---|
| More false-premise wordings, more premise examples, rank 64 | No trap improvement; rank 64 learned template denial without better strict scores |
| Stronger null-space protection, halved learning rate, EMA averaging | Did not solve L5 |
| Books 2–4 reduced from 12 to 8 epochs | Knowledge stayed high and MMLU was unchanged; only which L5 checkpoints failed changed |
| Book 1 reduced to 4 epochs | Better L5, but knowledge fell to 133 |
| All row types with fewer premise rows | GSM8K fell sharply in both seeds |
| Programmatic statement + question rows | Harmful alone; combined with teacher rows, the second trap exam worsened; more rows further hurt MMLU |
| Client-listed dead ends: 15–100% replay, L2-SP, TIES/DARE, adapter summation, self-distillation, trap DPO, 10–15% general-data mixing, contrast/refusal rows, in-context premise checking, MMLU multiple-choice format blocks, reference chains, verifier adapters, joint training, adapter scaling | Explicitly rejected by the recorded terms; do not propose them as a repetition of those failed approaches |

## 10. Running an experiment (original Colab G4 environment)

1. Rebuild local bundles: `bash tools/build_bundles.sh /tmp/b`.
2. Start a machine only after stating duration/cost and getting user approval: `colab_new name=genNN accelerator=G4 max_minutes=…`.
3. Upload:
   - `/tmp/b/cl.tgz` as `/content/cl_v60.tgz`.
   - `/tmp/b/chat_self_7b.json` as `/content/chat_self_7b.json`.
   - `rclone.conf` as `/content/rclone.conf`.
   - `/tmp/b/l5.tgz` under the name expected by the cell (`l5f.tgz` / `l5g.tgz` / `l5n2.tgz`).
   - `/tmp/b/hf_trap_answers.py`.
   - The JSON configuration needed by the cell as `/content/run_cfg.json`.
4. Launch: `colab exec -s genNN -f tpu/cells/<cell>.py`. The cell starts a background script through `nohup`; its log syncs every minute to `gdrive:kaggle/genNN-<date>/live/genNN.log`.
   - `run_cell61/62/63.py`: book 1 only + L5.
   - `gen24/25_cell.py`: load book-1 factors, train books 2–4, measure L5 after every book.
   - `heldout1_cell.py`: held-out-combination test.
   - `noise_cell.py`, `infer_cell.py`: variation tests and inference of base evaluation settings.
5. Keep alive: `colab exec -s genNN -f tools/ping.py` every 8 minutes; otherwise the VM may be reclaimed after about 20–30 minutes without interaction.
6. Watch the log: `rclone cat gdrive:kaggle/genNN-<date>/live/genNN.log`.
7. Finish: first run `rclone copy gdrive:kaggle/genNN-<date>/ tpu/results/genNN-<date>/ --exclude "lora/**"`, score with `lab/score_strict.py`, **stop the machine with `colab_stop` immediately after retrieving results**, then document the results in `tpu/JAX_PLAN.md` and commit.
